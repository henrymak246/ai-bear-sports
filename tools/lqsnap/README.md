# tools/lqsnap/ — 篮球盘口位移归档

**这份归档不可再生。** 两个数据源(官方 webapi / 出奇 odds)都只返回当前值、不给历史 ——
实测同一个 eventid 隔两次调用盘口就变了，而 odds 表里每 `(eventid, supplierid)` 恒只有 1 行。
错过一次 = 那一段位移永久消失。

## 为什么不能拿 `tools/lqpool_*.json` 回测

`lqpool_*.json` 是**用当前快照重建**的(实测 11 个文件的 `source` 全部指向同一天早上 07:56/07:57)，
用它回测会得到 96% 这种物理上不可能的假命中率。

**只有本目录下的快照是「当时真的是多少」。**

## 结构

```
<YYYYMMDD>/<HHMM>.json    一轮归档(同一分钟内再跑会追加 -2/-3 后缀，绝不覆盖)
state.json                计数器(本地运行状态，不进 git)
```

顶层字段：

| 字段 | 含义 |
|---|---|
| `ts` | 归档时刻(北京时间) |
| `day` | 归档日 |
| `source` | 本轮所用的 `lq_<MMDD>.json` / `lqodds_<MMDD>.json` 文件名 |
| `official` | 官方四池(hdc/hilo/mnl/wnm) —— 竞彩固定奖金产品，冻结在收盘 |
| `poolList` | 单关/过关可用性 —— 官方只给**当前在售**，下架即永久消失 |
| `odds` | 出奇博彩盘，按白名单过滤后仅留篮球 |

## ★★ 读 `odds` 前必须知道：污染是不对称的

`official`(≡ 出奇 sup51)是**真·赛前线**；`odds` 里其他博彩公司行，对**已完赛 / 取数时已开赛**
的场次是**滚球或结算值** —— 逐家 MAE 实测 **1.5~5.0 分**，而篮球真实赛前线 MAE 在 **9~13 分**，
1.5~5.0 物理上不可能。(另有 15/55 场的博彩盘中位数与真实净胜相差 ≤0.5 分 ⇒ 铁证是赛后值。)

判据 —— 两个必要条件**层次不同，别只判一个**：

```
played === true          → 结算值(必要不充分)
tipoff > 该快照的 ts      → 取数时尚未开赛，才是干净的赛前线
```

只判 `played` 会漏掉滚球值：实测 周二304 开赛 07:30 / 取数 07:57(已打 27 分钟)，而它 `played` 仍是 `false`。

## 格式演进

- `20260923/0811.json`、`0910.json` —— **老格式，无 `poolList` 段**(实现 bug：digest 算了 poolList
  但落盘漏写)。这两份的 poolList **已永久丢失，不可补** —— 补进去的是当前值，会伪装成历史值。
- 自 `20260923/1028.json` 起带 `poolList`。

## 白名单

`odds` 按 **今天 ∪ 昨天** 的 `lqpool_*.json` 取 eventId 过滤(不取全量：出奇 `/odds/data` 是含足球的
全量封套，实测 575 场里篮球仅 58 场 = 6.6%，原样存 = 93.4% 噪音 · 3.4GB/年)。

取两天是因为**竞彩期号 D 覆盖 [D凌晨, D+1上午]** —— 昨天期号的比赛今天上午才开打，那几小时恰恰是
位移最活跃的窗口(2026-09-23 实证：周二304~308 于 9-23 07:30~10:00 开打)。

白名单缺失时**不过滤 + 显式告警**，宁可存胖，绝不静默砍数据。
