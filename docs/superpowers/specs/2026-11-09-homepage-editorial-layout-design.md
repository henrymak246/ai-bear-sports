# 主页每日发布与投资策略置顶设计

日期：2026-11-09
状态：已获用户口头确认布局与内容范围
范围：`index.html`、`data/predictions.js`、相关冒烟测试；不改变预测、结算与推荐规则。

## 1. 目标

主页优先回答两个问题：小熊今天如何完整复盘与解释判断，以及资金如何分层管理。每日发布与投资策略因此前移至每日预测之前，并以完整段落说明分析过程，不再只给精简口号。英超、日韩等联赛内容统一归入专栏区。

## 2. 已确认方案

采用 A「双核心纵向置顶」。桌面与手机均按「每日发布 → 投资策略」纵向排列，避免长文和四列表格在桌面双栏中过度拥挤。每日发布与投资策略保持两个独立面板，便于维护和查阅历史记录。

## 3. 页面结构

`sec-today` 保留海报和四项成绩卡，其后顺序固定为：

1. `dailyPostBox`：每日发布完整长文。
2. `investPanel`：投资策略详述与近 7 日方案表。
3. `dailyList`：每日预测总览。
4. 现有方案、梦想 7 关、三时段票、亚盘、比分和足彩区域，相对顺序不变。

`investPanel` 从 `sec-columns` 移至 `sec-today`。`sec-columns` 保留英超面板，并恢复日韩面板 `jkPanel`/`jkBody`；`renderJK(days)` 恢复主动调用。篮球仍保留在独立篮球区，不改变现有导航。

## 4. 每日发布内容

将 2026-11-08 的字符串式精简 `dailyPost` 改为带 `title` 与 `content` 的对象。正文只使用已核验的 30 场赛果、终审统计和资金口径，分为五部分：

1. **整体成绩**：方向 17/30、双选 23 红 4 黑、8 场平局全罩，胆与单选分别说明。
2. **关键场分析**：切尔西双热仍黑、米兰撤单改双的原因、早场日韩浅盘问题、欧战硬闸撤腿及其纪律成本。
3. **产品逐项复盘**：亚盘、大小球、比分、北单、足彩、三时段票与梦想 7 关分别说明，不合并成一句概括。
4. **资金口径**：61 元主方案、可计算回收约 298.26 元、名义净约 +237.26 元；大小球因赔率未留档不计回收；128 元足彩为展示票。
5. **模型改进**：强热不自动升单选、任九胆独立复核、三时段票控制单锚与重复暴露、大小球赛前留存真实赔率。

渲染器继续兼容历史对象的 `content`/`text` 字段，同时兼容字符串形式 `dailyPost`，避免旧数据消失或错选陈旧日期。正文先 HTML 转义，再支持既有 `**加粗**` 与换行显示，不引入第三方依赖。

## 5. 投资策略内容

保留近 7 日每日方案表和合规提示，在三层策略表前增加完整导读，并为每层补足：

- **稳定层**：胆的 SP 与信息面条件、仓位来源、空仓条件、单选和胆分开统计的原因。
- **增强层**：亚盘与大小球的用途、串关风险、半红/走水结算、赔率留痕要求。
- **彩票层**：北单、足彩、任九和展示票的预算边界，超预算只展示，不通过加注弥补前一日亏损。

每层使用完整段落解释「做什么、为什么、何时不做、如何复盘」，近 7 日表继续由每日 `plan` 中「💰 投注建议」自动生成，不复制额外数据副本。

## 6. 数据流与兼容

- 页面仍从本地 `PREDICTION_DAYS` 与 Supabase 日数据读取，不新增接口。
- 每日发布延续现有逻辑，选择最新一份含有效内容的发布；投资策略继续展示最近 7 条资金方案。
- 不改 `stats.js`、小程序判定、东京盯梢或足彩/北单结算。
- 无每日发布时保持空态；无日韩数据时显示现有友好空态。

- 专栏区包含英超与日韩，不再包含投资策略。
- 11-08 每日发布为完整对象并包含五部分详细内容；字符串形式历史数据仍能渲染。

- 既有 `check_daily`、slot8/stats/mini_judge、网站渲染和小程序相关测试保持通过。

使用桌面与约 390px 手机视口检查实际渲染，重点查看长文换行、表格横向滚动、面板间距与专栏空态。运行一次 Impeccable 机械检测，区分类目既有告警与本次新增问题。

## 8. 上线边界

数据变更同步东京与 Supabase。实际网站由 GitHub Pages 承载，`index.html` 必须提交并推送后才会上线；任何 git 提交或推送均需用户在执行前另行确认。本次不改小程序界面，不重新上传微信开发者工具。
