# 方案层命中率统计 · 设计文档

日期：2026-07-27
状态：已确认（用户逐节通过）

## 背景与目标

现状：站点已统计「每场预测」的方向/大小球/比分命中率（来自 `matches[]`），但首页方案方块（`plan[]`：胜平负/进球数/比分/过关串关/亚洲让球/大小盘）只有文字、没有红黑追踪，无法回答"哪类方案最赚钱"。

目标：给每个方案块追踪红黑结果，新增「方案层命中」汇总面板，按方案类型累计命中率。

非目标（YAGNI）：不做方案块内逐腿（leg）结构化、不做模拟盈亏/ROI、不做复盘教训标签。

## 总体方案

方案 A：关键词归组 + 块级手动回填。

- `plan[]` 每项新增一个可选字段 `result`，复盘时与 `finalScore`/`review` 一起手动回填
- `stats.js` 按 `market` + 名称关键词把方案块归成 6 类，纯函数统计
- `index.html` 主区加汇总面板展示

## ① 数据格式（data/predictions.js）

`plan` 每项新增可选字段：

```js
{ market: 'jc', name: '🎯 胜平负', pct: '50%', text: '…', result: 'hit' }
```

- 取值：`'hit'`（红）/ `'miss'`（黑）/ `'half'`（半红）/ `'push'`（走水）
- 缺省或 `null` = 未回填，不计入统计
- 一个块内含多个独立选项时，按该块整体战果判定（全红=hit，全黑=miss，部分红=half，全部走水=push）；判定依据写进当日 `review`
- 其余字段（`detail`/`fivePillars`/`actualBets` 等）不变

## ② 统计逻辑（stats.js）

新增两个纯函数（不碰 DOM，Node 可测）：

`planTypeOf(market, name)` → 6 类之一：

| 类型 | 规则 |
|---|---|
| 大小盘 | `market==='std'` 且名称含「大小」 |
| 亚洲让球 | `market==='std'` 其余 |
| 比分 | `market` 非 `std` 且名称含「比分」 |
| 进球数 | 名称含「进球」 |
| 过关串关 | 名称含「过关」或「串」 |
| 胜平负 | 其余（含「让球+胜平负 · 底仓/增益」等竞彩方向块） |

归组优先级按上表自上而下；`market` 缺省按 `'jc'` 处理。

`planStats(days)` → 每类输出：

```js
{ hit, half, miss, push, total, rate, last14: [/* 已回填块 { date, result }，日期升序，最多 14 条 */] }
```

口径（沿用现有规则）：

- `hit`=1、`half`=0.5 计入分子；`total = hit + half + miss`（走水 push 与未回填不计入分母）
- `rate = (hit + 0.5*half) / total`，`total===0` 时 `rate=null`
- `last14` 取已回填块（含走水）按日期升序的最近 14 条

## ③ UI（index.html）

- 主区命中率仪表盘旁新增「🎯 方案层命中」面板，6 行（类型固定顺序：胜平负/进球数/比分/过关串关/亚洲让球/大小盘）
- 每行：类型名 + `X红X黑`（半红、走水有则单列）+ 命中率百分比 + 近14次迷你圆点（复用左栏红黑圆点样式）
- 某类 `total < 3` 时百分比位置显示「样本不足」灰字
- 方案方块与日卡详解弹窗中，已回填的块显示结果徽标：🔴 hit / ⚫ miss / 🌗 half / ➖ push
- 样式沿用现有卡片与配色；移动端随现有响应式，无新增断点

## ④ 测试与回填

`test/stats.test.js` 新增 `planStats`/`planTypeOf` 用例：

- 归组边界：`'🟢 让球+胜平负 · 底仓'`→胜平负；`'🔵 亚洲让球'`→亚洲让球（不误入胜平负）；`'🎯 过关专栏'`→过关串关；`market` 缺省按 jc
- `half` 计 0.5、`push` 不计入分母、未回填（无 `result`）不计入
- `total===0` 时 `rate===null`；`total<3` 样本不足判定
- 现有全部用例保持通过
