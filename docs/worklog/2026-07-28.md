## 二、站长后台管理面板（已完成 ✅ b367b95..81beac6）

全流程：brainstorming → 规格 → 实施计划 → 子代理执行（每任务规格+质量双审）→ 终审 → 部署门上线。

- **需求**：站长不碰数据库，在站内完成会员审核/撤销 + 数据状态查看；注册加邮箱确认
- **实现**：`members.is_admin` 列 + 4 个 security definer RPC（函数体内鉴权，members 表保持无前端写策略）；站内用户条「🛠 管理」→ 三区块面板（待审核/会员管理/数据状态）；注册四态门（注册→📧邮件确认→🍯等审核→内容）
- **质量审查抓出的两个真缺陷**（已修，`190feff`）：
  1. `revoke ... from anon, authenticated` 是空操作——PostgreSQL 默认把函数 EXECUTE 授给 PUBLIC，必须连 PUBLIC 一起收（否则匿名仍可调 RPC，仅靠函数体鉴权兜底）
  2. `is_admin()` 不查 approved——被撤销的管理员可 `approve_member(自己)` 恢复资格；已加 `and approved`
- **部署顺序铁律**：`admin.sql` 先于前端 push（否则 `select('approved, is_admin')` 报错，全员误判等开门）——按序执行未出事故
- **负向验证（curl）**：匿名调 `approve_member`/`list_members` → 42501 permission denied for function ✓；匿名读 members → [] ✓
- **站长赋权**：`node tools/set-admin.js maixiong@chinasie.com`（service key 置 is_admin+approved，用户零 DB 操作）
- **踩坑 2**：邮件确认链接跳错地址——Site URL 未保存（Supabase 默认 localhost:3000）。点击链接时验证本身已生效，仅回跳错误；重新保存 Site URL + Redirect URLs 即可
