# 云函数通道（真机可用）

## 为什么需要它

真机（预览版/体验版/正式版）会校验 **request 合法域名**，而 `*.supabase.co` 属境外域名，
**无法完成 ICP 备案** → 配不进白名单 → 真机请求必然失败：

```
request:fail url not in domain list:gzpuxgkpblpbpdpfvpof.supabase.co
```

表现：推荐页显示 `⚠️ 推荐数据拉取失败,显示缓存` + **前一天的缓存数据**；组串保存同样失败（同一个域名）。
开发者工具里勾「不校验合法域名」只对模拟器生效；手机端必须「打开调试」才行（每次都要点）。

**根治**：小程序 → 云函数 `bear_api` → Supabase。云函数在腾讯云国内机房**出网**，
不受小程序侧域名白名单限制，手机不用开调试。

```
小程序 wx.cloud.callFunction({name:'bear_api', data:{fn, args}})
   → 云函数 index.js → core.js.callSupabaseRpc()
   → https://<proj>.supabase.co/rest/v1/rpc/<fn>  (带 MINI_TOKEN + anon key)
   → { ok:true, data } / { ok:false, error }
```

## 一次性开通（微信开发者工具，人工 1 分钟）

1. 打开小程序项目 → 顶部工具栏点 **「云开发」** → **开通**（个人主体可用，有免费额度）
2. **创建环境**（名字随意，如 `bear-prod`）→ 复制 **环境 ID**（形如 `bear-prod-1g0abc12de3456`）
3. 填进 `miniprogram/utils/config.js` 的 `CLOUD_ENV`

## 部署云函数

```bash
cd "C:/Users/Administrator/Desktop/足球预测站"
MSYS_NO_PATHCONV=1 "/c/Program Files (x86)/Tencent/微信web开发者工具/cli.bat" cloud functions deploy \
  --env <环境ID> --names bear_api --remote-npm-install \
  --project "C:\Users\Administrator\Desktop\足球预测站\miniprogram"
```

`--remote-npm-install` = 依赖在云端安装（本地不产生 node_modules）。

## 密钥放哪

优先级：**云函数环境变量** `SUPABASE_URL` / `SUPABASE_ANON_KEY` / `MINI_TOKEN`
（云开发控制台 → 云函数 → bear_api → 配置 → 环境变量）> 同目录 `config.js`。

ESPN 中转另有两个可选项，同一条优先级链：`ESPN_RELAY`（形如 `http://<节点IP>:8899`）与
`ESPN_RELAY_TOKEN`；**不配则自动退回直连 `site.web.api.espn.com`**（功能不变，只是慢）。

`config.js` 已 gitignore；虽不入库，但**会随函数包上传到微信云**，属可接受（仅自己可见）。
节点上的那份副本在 `/opt/espn-relay/env`（600, root）—— **全库只有这两处**，任何文档/提交里都不出现。

## 比分从哪来（2026-09-15 实测定稿）

**结论：真机比分走云函数，实时比分可用**（前提：云函数已部署 + 小程序 `config.js` 开 `ESPN_CLOUD`）。

### 403 是「主机名」问题，不是 IP 段封锁

2026-09-15 先测出云函数出网 403 + Akamai `Access Denied`，当时判成"IP 段封锁"。**这个判断是错的**：
同一台机器、同一份请求头，换主机名就通 —— `site.api.espn.com` 被 ESPN 自家 Akamai WAF 的
主机名规则挡掉，而 **`site.web.api.espn.com` 返回同一份 JSON 是 200**。

| 主机名 | 本机(国内住宅 IP) | 东京 Vultr | 腾讯云云函数 |
|---|---|---|---|
| `site.api.espn.com` | 200 | 403 | 403 |
| `site.web.api.espn.com` | 200 | 200 | **200** |

两主机的返回体结构完全一致（顶层 `{leagues,events,provider}`）。所以云通道本身是通的，
真机 `wx.request` 那条路才是真死（境外域名无法 ICP 备案 → 配不进 request 合法域名）。

**防回退**：主机名两处必须同步 —— 云函数 `core.js` 的 `ESPN_SCOREBOARD_HOST` 与小程序
`espn.js` 的 `boardUrl()`。冒烟 ⑬ 有专门断言卡这条，改回去真机比分就又是"永远空"。

### 那为什么还要中转（东京节点 `espn-relay`）

不是绕过封锁（换主机名已解决），是**躲超时**：云函数超时 **3 秒**，而腾讯云直连 ESPN 跨境单程
实测 1.7~3.3 秒 —— 三次里挂一两次，真机上就是"比分时有时无"。中转把跨境段换成
「腾讯云→东京(约 0.1s) + 东京→ESPN(约 0.5s)」。

中转实现见 `okx-proxy/espn-relay/relay.py`（部署在东京 `108.61.246.121`，systemd 服务
`espn-relay`，监听 8899/tcp）。**只转发 `soccer/<league>/scoreboard` 这一条路径**，
须带 `x-bear-token` 头；地址与令牌只存在于云函数的 `config.js`（已 gitignore），不入库。

### 三次优化，把云函数从"贴着超时线"拉回来

用 `args.perf` 逐段打点（`node tools/_diag_espn.js esp.1 20260915 8 --perf`）测出来的：

| 优化 | 手段 | 实测效果 |
|---|---|---|
| ① 缩包 | 中转侧归一化成 `{rows:[...]}`（40KB → 255B） | 方向对，但**不是瓶颈**（仍偶发 >3s） |
| ② 连接复用 | `core.js` 自建 `keepAlive` agent（Node 16 全局 agent 默认 `keepAlive=false`，每次都重新跨境握手） | 热容器 `建连=0ms` |
| ③ 结果缓存 | 中转侧按 (联赛,日期) 缓存 45 秒（`RELAY_CACHE_TTL`） | 削掉稳定的东京→ESPN 500ms |

效果：函数内出网 **1155~2679ms → 266~646ms**；连打 8 次全部成功（改前三次挂一两次）。

**剩下的不可控项**：腾讯云↔东京那一段本身的抖动（实测 TTFB 145ms~2678ms，同一连接复用下
依然如此），以及云函数 3 秒硬超时。对策两条：

- 小程序 `espn.js` 失败**重试一次**（`ESPN_CLOUD_RETRY`，只对只读取数，写操作绝不重试）；
- 想根治得在**云开发控制台 → 云函数 → bear_api → 配置 → 超时时间**改成 20 秒 ——
  CLI 没有这个参数、本机也没有腾讯云凭据，只能手工点一次（属可选保险，非必须）。

要点（与 Supabase 通道共用的部分）：
- 联赛码只做**形状校验**（`^[a-z][a-z0-9_]*(\.[a-z0-9_]+)*$`，≤32 字符）而非写死清单 ——
  每日场次会引入新联赛码（9-15 就新增 `eng.league_cup`/`afc.champions`/`conmebol.libertadores`），
  写死清单意味着每加一个联赛都要重新部署云函数。
- `espn_scoreboard` 分支**不校验 Supabase 配置**（在 `index.js` 里先于 `assertCfg` 分发），两者互不依赖。
- 小程序侧通道选择收在 `utils/espn.js` 的 `pickChannel()`：注入 fetcher > `ESPN_CLOUD` 云代理 >
  开发者工具直连 > 真机（立即失败）。结算轮询的去重取板器用 `espn.makeBoardFetcher(cache)`，
  **不要在页面里自己包 `defaultFetcher`**，那会绕过这层判断。
- 归一化口径有**跨语言漂移**风险（`relay.py` 的 `normalize()` 与 `core.js` 的 events 分支各写一份）。
  冒烟 ⑮ 用同一份 fixture 交叉核对两边结果必须逐字段一致 —— 改任一边的口径都会立刻红。

```bash
ssh nrt2 'cd /root && cat > relay.py.new && sha256sum relay.py.new' < espn-relay/relay.py
ssh nrt2 'install -m 644 -o root -g root /root/relay.py.new /opt/espn-relay/relay.py && rm -f /root/relay.py.new && systemctl restart espn-relay'
ssh nrt2 'journalctl -u espn-relay -n 20 --no-pager -o cat'   # 看 上游=xxxms / cache命中
```

## 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `云函数 bear_api 失败: 无返回` | 函数未部署 / 环境ID填错 | 重新 deploy；核对 `CLOUD_ENV` |
| `云函数配置缺失: MINI_TOKEN` | 环境变量与 config.js 都缺 | 补配置后重新 deploy |
| `不允许的调用: xxx` | 调了白名单外的函数 | 在 `core.js` 的 `ALLOWED_FNS` 里加 |
| `ESPN 联赛码非法: xxx` | 联赛码形状不合法 | 核对 `espn_matches.js` 的联赛码（形如 `eng.2`/`afc.champions`） |
| 真机场卡没有实时比分 | 云函数未部署 / `config.js` 没开 `ESPN_CLOUD` | 重新 deploy；`utils/config.js` 加 `ESPN_CLOUD: true` |
| `-504003 Invoking task timed out after 3 seconds` | 腾讯云↔东京抖动顶爆 3 秒超时 | 已有重试兜底；根治＝控制台把超时时间改成 20 秒 |
| 结算判不出结果 | 当日 `finalScore` 还没回填/没同步 | 本机跑 `node tools/_live<MMDD>.js` 回填 → `node tools/sync-data.js` 同步 |
| 云函数日志里有 `ESPN … HTTP 403` + `Access Denied` | 主机名被写回 `site.api.espn.com` 了 | 两处一起改回 `site.web.api.espn.com`（`core.js` + `espn.js`），冒烟 ⑬ 会红 |
| 云函数日志里有 `[relay] HTTP 403` | 令牌不一致 | 核对节点 `/opt/espn-relay/env` 与云函数 `config.js` 的 `ESPN_RELAY_TOKEN` |
| 中转日志出现 `502` / `upstream` | 节点侧出网异常 | `ssh nrt2 'journalctl -u espn-relay -n 50 -o cat'`，确认 sing-box/okx 服务未受影响 |
| 手机仍显示缓存 | `CLOUD_ENV` 为空 → 走了直连 | 填环境ID，重新预览 |
| 想看直连 | 调试用 | `config.js` 里 `USE_CLOUD: false` |
